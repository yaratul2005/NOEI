# AGENTS.md

> **Repository Context & System Guidelines for AI Coding Agents**  
> **Project Type:** Modern, Shared-Hosting-First PHP/MySQL Content Management System  
> **Target Environments:** Shared Hosting (cPanel, DirectAdmin, Apache, LiteSpeed, FTP/File Manager), VPS, and Docker

---

## 1\. Project Mission & Core Tenets

### 1.1 Core Mission Statement

> *"A modern CMS that is as easy to install as WordPress, as affordable as shared hosting, but faster, safer, cleaner, and more extensible."*

### 1.2 Guiding Principles

1. **Zero Mandatory Infrastructure Overhead:**  
   - The platform MUST run on standard, low-cost shared hosting with only PHP, MySQL/MariaDB, Apache/LiteSpeed, and HTTPS.  
   - Never require Node.js runtimes, Redis, Memcached, Docker, SSH, Composer on production, or root VPS administration for core functionality.  
2. **Security by Design:**  
   - Strict adherence to parameterized PDO queries (zero SQL string concatenation).  
   - Modern password hashing, mandatory CSRF validation, strict output escaping, secure file upload pipelines, and a permission-governed extension architecture.  
3. **Progressive Enhancement & Speed:**  
   - Server-rendered HTML first. JavaScript is used exclusively for progressive UX enhancements (no heavy SPA frameworks required to view or manage content).  
4. **Broad Internationalization (i18n):**  
   - Native `utf8mb4` encoding across database tables and connections to fully support Bangla, English, multilingual scripts, complex diacritics, and emojis.  
5. **Decoupled & Optional AI:**  
   - Any AI capability is an optional progressive enhancement via external API integrations. The CMS core must remain 100% functional without AI configured.

## 2\. Technical Stack & Architecture Baseline

| Component | Standard Specification |
| :---- | :---- |
| **Language & Runtime** | PHP 8.1+ (strict types enabled: `declare(strict_types=1);`) |

| **Frontend Strategy** | Semantic HTML5, server-rendered views/templates, lightweight progressive vanilla JS / micro-frameworks |
| **Asset Pipeline** | Pre-compiled/vanilla zero-build assets for distribution (no runtime NPM build required on server) |

## 4\. First Release Scope (Vertical Slice)

All development tasks must focus on delivering and refining the essential vertical slice:

1. **Browser-Based Installer:**  
     
   - Pre-flight validation: PHP version, required extensions (`pdo_mysql`, `mbstring`, `gd` or `imagick`, `curl`, `json`), and directory write permissions (`/config`, `/storage`).  
   - Interactive database connectivity check.  
   - Automatic execution of `schema.sql` under `utf8mb4`.  
   - Initial administrative user registration and `config/database.php` generation.  
   - Self-locking mechanism to disable the installer upon successful setup.

   

2. **Admin Dashboard:**  
     
   - Lightweight, responsive admin UI with system health metrics, recent activity feeds, quick content creation shortcuts, and storage overview.

   

3. **Content Engine (Pages, Posts, Categories, Tags):**  
     
   - Hierarchical Pages (parent-child relationships).  
   - Chronological Posts with publishing workflows (Draft, Scheduled, Published, Private).  
   - Taxonomy system (Categories and Tags) with slug generation.  
   - Content Revisions and autosave snapshots.

   

4. **Media Management:**  
     
   - Drag-and-drop file uploader with chunking support for low shared-hosting upload limits.  
   - Automatic thumbnail and responsive size generation via GD/Imagick.  
   - Media browser modal integrated into content editors.

   

5. **Users, Roles & Access Control (RBAC):**  
     
   - Default roles: `Administrator`, `Editor`, `Author`, `Contributor`, `Subscriber`.  
   - Granular permission checks (`can('post:edit')`, `can('user:manage')`).

   

6. **Themes & Menu Management:**  
     
   - Theme switching architecture with template override hierarchy.  
   - Visual drag-and-drop navigation menu builder supporting multi-level nested menus.

   

7. **SEO & Metadata Controls:**  
     
   - Canonical URLs, custom title tags, meta descriptions, and Open Graph / Twitter Card tags.  
   - Automated dynamic XML sitemap generation (`/sitemap.xml`).  
   - Configurable `robots.txt` manager.

   

8. **Secure Extension (Module) System:**  
     
   - Manifest-based module registration (`module.json`) declaring required permissions (e.g., `storage:write`, `database:table_create`, `network:curl`).  
   - Safe hook system (`Actions` for execution triggers and `Filters` for content transformations).  
   - Explicit prevention of unrestricted raw script execution outside the sandbox lifecycle.

   

9. **Backup & One-Click Update System:**  
     
   - Version check against remote release endpoints.  
   - Automated pre-update snapshot (database SQL dump and core file backup into `/storage/backups/`).  
   - File replacement with automatic rollback capability if database migration or file extraction fails.

   

10. **Core REST API:**  
      
    - RESTful endpoints for headless retrieval (`/api/v1/posts`, `/api/v1/pages`, `/api/v1/categories`).  
    - API Key and Bearer token authentication for external access.

## 5\. Security & Data Integrity Requirements

AI agents modifying or writing code for this repository must strictly adhere to the following rules:

### 5.1 Database Operations

- **Rule:** Never use raw SQL string interpolation or concatenation.  
- **Implementation:** Always use PDO prepared statements with explicitly bound parameters.

// CORRECT

$stmt \= $pdo-\>prepare("SELECT id, title, content FROM cms\_posts WHERE slug \= :slug AND status \= :status LIMIT 1");

$stmt-\>execute(\['slug' \=\> $slug, 'status' \=\> 'published'\]);

$post \= $stmt-\>fetch();

// STRICTLY FORBIDDEN

$pdo-\>query("SELECT \* FROM cms\_posts WHERE slug \= '" . $slug . "'");

### 5.2 Character Encoding & Internationalization

- All database connections must execute `SET NAMES utf8mb4 COLLATE utf8mb4_unicode_ci` upon connection.  
- All database tables must specify `ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci`.  
- All HTML templates must output `<meta charset="UTF-8">`.

### 5.3 Authentication & Session Security

- Use native `password_hash($password, PASSWORD_DEFAULT)` for credential storage.  
- Validate logins using `password_verify($password, $hash)`. If `password_needs_rehash($hash, PASSWORD_DEFAULT)` is true, re-hash and update the record.  
- Always regenerate session IDs on login and privilege escalation: `session_regenerate_id(true)`.  
- Enforce strict cookie security: `SameSite=Lax` (or `Strict`), `HttpOnly`, and `Secure` when on HTTPS.

### 5.4 Input Validation, CSRF & XSS Prevention

- **CSRF Tokens:** All `POST`, `PUT`, `PATCH`, and `DELETE` requests must validate a cryptographic session CSRF token.  
- **Output Escaping:** Escape dynamic data rendered in HTML context using a helper:

function e(?string $value): string {

    return htmlspecialchars((string)$value, ENT\_QUOTES | ENT\_SUBSTITUTE, 'UTF-8');

}

- **Upload Security:**  
  - Verify file MIME types using `finfo_file` (do not rely on user-supplied file extensions).  
  - Store uploads outside web root or disable script execution in upload directories via `.htaccess`:

\# storage/uploads/.htaccess

\<FilesMatch "\\.(php|phtml|php3|php4|php5|php7|php8|phar|pl|py|cgi)$"\>

    Deny from all

\</FilesMatch\>

## 6\. Coding Standards & Agent Workflow Rules

### 6.1 PHP Code Conventions

- Follow **PSR-12** formatting and **PSR-4** autoloading standards.  
- Declare `declare(strict_types=1);` at the top of every PHP file.  
- Use explicit typehints and return types on all functions and class methods.  
- Favor clean composition and dependency injection over heavy static state.

### 6.2 Error Handling & Logging

- In production mode, display clean user-facing error pages without exposing stack traces, paths, or database credentials.  
- Write structured error traces into `/storage/logs/cms-YYYY-MM-DD.log`.

### 6.3 Shared Hosting Compatibility Constraints

- Code must run within standard resource limits: `memory_limit` of 64M–128M, `max_execution_time` of 30–60 seconds.  
- Provide a pure-PHP fallback autoloader so that release zip files can be unpacked and run without executing `composer install` on the target host.  
- Do not assume shell execution functions (`exec`, `shell_exec`, `system`, `proc_open`) are enabled, as shared hosts frequently disable them via `disable_functions`.

## 7\. AI Agent Development Checklist

When creating or modifying features in this repository, ensure:

- [ ] All database queries utilize PDO prepared statements with bound parameters.  
- [ ] UTF-8 / `utf8mb4` encoding integrity is preserved across all inputs and queries.  
- [ ] CSRF verification is present on all state-changing endpoints.  
- [ ] Output variables are escaped using `e()` or equivalent safe templating functions.  
- [ ] Code runs on PHP 8.1+ without third-party daemon requirements.  
- [ ] No Node.js build step is required for runtime operation.  
- [ ] Any added module or feature cleanly registers with the hook/event architecture.  
- [ ] New database alterations include an automated migration step for the installer and updater.
